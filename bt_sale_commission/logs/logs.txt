V1.0.0 By Basil Khan AH
    1. A commission plan set to "Sale Order Line" attribution replace Odoo's native flat-rate/target-rate commission calculation with a per-row Python formula, and attributes achievement to each line's own salesperson instead of the order header.

V2.0.0
    1. Reworked to be partner-based: res.partner "Sales Person" flag; salesperson_partner_id on sale.order and sale.order.line; plan lists partners (Sales People (Partners) tab); achievements and commission per partner and target period via the plan's Commission Formula; new "Commission by Sales Person" report; native Commission report menu re-pointed to it.
    2. Removed the user-based overrides of sale.commission.achievement.report and sale.commission.report.

V2.0.1
    1. Restored the original design guidelines: only 'Sale Order Line' plans use the partner engine; native 'Sale Order' behaviour untouched; per-line attribution; formula contract. Documented the one departure (a new partner report model) and why.
    2. Native Commission menu re-pointing is now opt-in (system parameter bt_sale_commission.repoint_native_report = 1).
    3. Existing orders/lines with an empty sales person partner are back-filled from the old salesperson's partner on every install/upgrade, so history is not empty.
    4. Rebuild logs which plans/partners/periods it found, to diagnose empty reports.

V2.0.2
    1. Report is rebuilt by the menu entry (server action) and a 15-minute scheduled action, not during read RPCs (avoids writes in read-only requests).
    2. New menu Sales > Reporting > Commission Setup Check: states why the report may be empty (plan state, Attribution Level, partners, lines in target periods, lines without a sales person partner).

V2.0.3
    1. Native Commission AND Achievements report menus now open the partner-based reports by default (they are user-keyed, so were empty for partners). Disable: system parameter bt_sale_commission.repoint_native_report = 0.
    2. New "Achievements by Sales Person" report (confirmed order lines per sales person partner, list and pivot).

V2.0.4
    1. Buttons on the plan form that open the native user-keyed Commission / Achievements lists (e.g. "Related commissions") now open the partner-based reports, filtered by the plan. These actions are built in Python, so menu/action re-pointing did not cover them.

V2.0.5
    1. Sales People (Partners) is now a one2many tab like the native Sales People tab: partner, From, To, Other plans. Only order lines dated inside the partner's From/To (and the plan's dates / target periods) count; commission rows are per partner period.
    2. "Other plans" lists the other plans the partner belongs to for an overlapping period. The old hard block on overlapping plans was removed (overlaps are shown, not prevented).
    3. Partners of older versions are migrated into the new tab on upgrade.

V2.0.6
    1. Attribution Level "Sale Order": the Sales Person (Partner) on the sale order earns commission on the order's untaxed total (res.partner instead of res.users). Works for both attribution levels; Sales People (Partners) and Commission Formula tabs are shown for both.
    2. Commission report shows the Attribution Level; new report "Achievements by Sales Person (Orders)"; Setup Check counts orders as well as lines.

V2.0.7
    1. The plan's partner list now mirrors native sale.commission.plan.user: same fields (From defaults to the plan start, To), unique partner per plan, assignment must lie inside the plan period, "Other plans" computed like native (draft/approved plans with overlapping dates). It replaces the native res.users "Sales People" tab, which is hidden; the partner tab is named "Sales People".

V2.0.8
    1. Attribution Level "Sale Order": commission now comes from the plan's Commissions tab (sale.commission.plan.target.commission): achieved / target = completion rate, commission linearly interpolated between the surrounding table rows (0 below the first row, last row's amount beyond it). If the table is empty or the period has no target amount, the Commission Formula is used as before. "Sale Order Line" plans are unchanged (formula).

V2.0.9
    1. Fix: the Commission Formula (Attribution Level "Sale Order Line") always gave 0 because safe_eval(mode="exec") ran on a copy and its result was discarded. It now uses nocopy=True so result / result_type are read back.

V2.0.10
    1. Commission Setup Check now explains Attribution Level "Sale Order Line" plans per partner: confirmed lines carrying the partner, lines inside the periods/dates, lines left after the Achievements-tab product/category rules, lines with an empty line sales person, and lines belonging to partners not on the plan.

V2.0.11
    1. Commission rows get a "Formula Note" column: when the Commission Formula raises, or leaves result / result_type unset or invalid, the reason is shown on the row instead of a silent 0.
    2. Achieved Rate is stored as a ratio (1.0 = 100%) so the percentage widget no longer shows 100x the value.

V2.0.12
    1. Fix: safe_eval() of this Odoo version has no nocopy argument (TypeError shown in the Formula Note). The formula's result / result_type are now read back through a shared dict, which works whether or not safe_eval copies the context.

V2.0.13
    1. The sales person fields of sale.order and sale.order.line are now independent: "Order Sales Person" (header, used by Attribution Level "Sale Order") and "Line Sales Person" (each line, used by "Sale Order Line"). The line value is no longer computed/copied from the order and the upgrade no longer fills empty lines from the header. Existing line values are kept.


V2.1.0
    1. Manual adjustments (sale.commission.achievement, "Add to" / "Reduce From") now work partner-wise: new fields add_partner_id / reduce_partner_id point at the plan's Sales People lines (the native res.users fields are untouched).
    2. Commission by Sales Person: the net adjustment dated inside each target period (and inside the partner's From/To) is added to Achieved, shown in a new "Adjustments" column, and available to the Commission Formula as `adjustment`. A partner with only adjustments and no sales still gets a row.
    3. New menu Sales > Reporting > Adjustments by Sales Person (list/form/search) to enter and review them; Commission Setup Check counts adjustments too.

V2.1.1
    1. The native Adjustments (sale.commission.achievement) screens no longer show the user-wise fields "Add to" / "Reduce From" (res.users plan lines): they are hidden and the partner-wise fields (sales person of the plan) take their place in list and form views; search filters, group-bys and pivot/graph fields use the sales person as well. Applied when each view is loaded, so it does not depend on the native view xml ids.
    2. In those screens one of the two partner fields is required. Adjustments entered earlier with the user fields are kept but show no partner and are not counted in the partner report.

V2.1.2
    1. Commission by Sales Person is rebuilt as soon as a partner adjustment is created, changed (amount, date, currency, company, sales person) or deleted. Before, it only refreshed from its own menu or the 15-minute scheduled action, so a new adjustment looked as if it did nothing.


V2.2.0
    1. New field "Sales Person" (res.partner, flagged Sales Person) on account.move and account.move.line, for customer invoices and credit notes only (out_invoice / out_refund). Defaults from the sale order's Order Sales Person (header) and the order line's Line Sales Person (line); both stay editable. A credit note made with Reverse copies the values of the invoice.
    2. Two new Attribution Levels on the commission plan: "Invoice" (account.move) and "Invoice Line" (account.move.line).
    3. Both levels are based on POSTED customer invoices minus credit notes (untaxed, company currency, by invoice date): achieved = amount invoiced - amount credited. Down payment lines are left out.
    4. "Invoice Line": commission by the Commission Formula, exactly like "Sale Order Line". "Invoice": commission from the plan's Commissions tab (formula as fallback), exactly like "Sale Order".

V2.2.1
    1. Fix: Sales Person on account.move / account.move.line is now a plain stored field (filled from the sale order at creation only). The stored compute with readonly=False re-derived the value from the sale order and overwrote what was typed on the invoice / invoice line, so Invoice and Invoice Line plans saw the wrong (or no) sales person.
    2. Fix: Commission by Sales Person is rebuilt when an invoice is posted, reset to draft, cancelled, or its sales person / invoice date changes (before, it only refreshed from the menu or the cron).
    3. Commission Setup Check explains Invoice / Invoice Line plans (posted lines, lines carrying a sales person, per partner).

V2.3.0
    1. Attribution Level is now ONLY Invoice (account.move) or Invoice Line (account.move.line); the sale order levels were removed (existing plans are migrated: sale order -> Invoice, sale order line -> Invoice Line).
    2. Amounts are the UNTAXED amounts of posted customer invoices minus credit notes (company currency), by the Sales Person (res.partner) of the invoice / invoice line.
    3. Invoice: same rules as the old sale order level (Commissions tab table, formula as fallback).
    4. Invoice Line: the Commission Formula now runs once per account.move.line with the variables of that line (line, move, product, price_subtotal, quantity, price_unit, discount, sign); row commission = sum of the lines.

V2.3.1
    1. Invoice level: the plan's Python formula now decides the commission (once per sales person and target period, amount_invoiced = untaxed invoices - credit notes). The Commissions-tab table is no longer applied silently: use target_completion and target_commission(completion) inside the formula (or leave the formula empty to use the table).
    2. Invoice Line level: formula runs per account.move.line with amount_invoiced / qty_invoiced / achievement / achievement_rate of that line.

V2.3.2
    1. Commission is derived from Achieved: a row whose Achieved is 0 gets no commission (before, flat 'amount' results or lines with 0 untaxed amount could still pay). Invoice lines whose untaxed amount is 0 are skipped.
    2. Invoice Line formula: achieved = the line's untaxed amount (what it adds to the row's Achieved), row_achieved = the row's total Achieved.

V2.3.3
    1. Default formula and help list every variable (plan, partner, total_sold, achieved, amount_invoiced, adjustment, total_sold_qty, target, target_amount, target_completion, target_commission, date_from, date_to, currency, company, row, env) plus the invoice line variables.
    2. Upgrade replaces the old default template (sale order wording) stored on existing plans; edited formulas are left alone.

V2.4.0
    1. The Commission Formula runs ONCE per row at both Attribution Levels; achieved / total_sold / amount_invoiced = the partner's total of the row (before, Invoice Line ran per line and achieved was one line's amount, so formulas comparing achieved with a target never matched).
    2. New variables: company_target, company_achieved (all sales people, same invoice rules, credit notes subtracted), lines, moves, line_amount(l), line_qty(l).
