V1.2.0 By Rijas Saju
    1. Chatter/audit trail: every generated journal entry (source + counterpart) now
       posts a chatter note explaining its origin (payslip, employee, period, paying &
       receiving company, amount). The payslip gets a summary note listing what was
       generated, and a note listing the entries removed when a payslip is cancelled
       or reset.
    2. No auto-post: intercompany entries are now created in Draft and never posted
       automatically. Posting is a manual, reviewed step.
    3. Cancellation via unlink: cancelling (or resetting) a payslip now removes ALL
       related entries - both the source entry and the target-company counterpart.
       Posted entries are reset to draft first, then unlinked. The unlink action is
       recorded in the payslip chatter.
    4. Cross-company access fix: generating the entries on validation performs every
       target-company read/write (company name, accounts, journal, partner and the
       counterpart creation) with sudo, so a payroll user who is not a member of the
       receiving company can validate without an "Access Error" on res.company.
       company_id is always set explicitly, so the booked entries are unchanged.
    5. Professional refactor (no functional regressions):
       - Counterpart creation is now explicit at generation time instead of being a
         hidden side effect of posting. The _post() override was removed.
       - Counterpart amount is taken from the same computed figure as the source
         entry (fixes a latent source/counterpart amount mismatch).
       - Counterpart entries are now tagged (is_intercompany_salary_move + role) so
         they appear in the Intercompany filter and can be grouped by role/payslip.
       - Idempotent counterpart lookup prevents duplicate entries on regeneration.
    6. Codebase cleanup: removed all non-docstring inline and section comments from
       the Python and XML sources for a clean, production-ready module (no logic,
       structure or behaviour changed).
